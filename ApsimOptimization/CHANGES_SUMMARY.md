# Обзор изменений ApsimOptimization

Главное изменение: добавлены планирование севооборота, расчёт выбранной карты в APSIM и многолетняя оптимизация управления культурами за 2020–2023 годы. Карта на 10 полей фиксируется до NSGA-II; алгоритм подбирает параметры посева и удобрения. Осень 2018 года и 2019 год используются для формирования состояния модели.

## 1. Какие входные файлы добавились

| Файл | Содержимое и назначение |
|---|---|
| `data/rotation/source/Севообороты.xlsx` | Исходная таблица совместимости предшественников и последующих культур.|
| `data/rotation/rotation_transition_matrix.json` | Машиночитаемая матрица из таблицы: каталоги культур, коды переходов и оценки 1 / 0,5 / 0. Вход планировщика севооборота. |
| `docs/20260804_ВНИИМЗ_трансекта/20260804_ВНИИМЗ_трансекта.xlsx` | Книга хозяйства. По ссылкам в конфигурациях — источник фактических предшественников и структуры посевов. Значения перенесены в YAML;|
| `data/rotation/selected_rotation_2019_2023.json` | Уже выбранная последовательность культур по каждому из 10 полей за 2019–2023 годы. Вход APSIM replay и оптимизатора. Это выбранный результат предыдущего планирования, сохранённый как вход следующего этапа. |
| `data/calibration_weather/weather_irgina_2018.met` | Суточная погода за 2018 год для предварительного периода с 01.09.2018. Дополняет существующую погоду 2019–2023 годов. |

Новые конфигурации:

| Файл в `configs/` | Для чего нужен |
|---|---|
| `rotation_planning_2019_2023.yaml` | Построение ретроспективной карты с учётом предшественников 2018 года, возраста травостоя и структуры культур хозяйства. |
| `rotation_planning_2019_2023_all_crops.yaml` | Расширенный эксперимент: дополнительно допускает вико-овсяную смесь, горчицу и рапс. Переходы для горчицы и рапса задаются по истории хозяйства. |
| `rotation_planning_2025_2029.yaml` | Планирование карты на 2025–2029 годы от состояния полей 2024 года. Этот сценарий строит последовательности культур без прогноза APSIM на будущие годы. |
| `multiyear_rotation_replay_2019_2023.yaml` | Связывает базовую APSIM-модель, выбранную карту, погоду, площади полей и календарь операций; включает предварительный период 2018 года. |
| `multiyear_rotation_nsga2_2020_2023.yaml` | Главный вход нового оптимизатора: годы оценки, варианты сорта, густоты, глубины, междурядья, формы и дозы N, экономические параметры и ограничения. |
| `multifield.yaml` | Шаблон с незаполненными агрономическими и экономическими параметрами (`null`). Требует заполнения; не является основным готовым сценарием. |

В двух существующих конфигурациях — `multifield_2023_n_diagnostic.yaml` и `multifield_historical_replay.yaml` — локальный абсолютный путь к APSIM заменён на `Models`, чтобы конфигурации не зависели от каталога конкретного компьютера. В диагностическом YAML также уточнён комментарий.

Базовая модель `simulation/calibrated/full_field2019_2023_calibrated_v3.apsimx` и основной погодный файл `data/weather/weather_2019_2023_units_corrected.met` в этом diff не изменяются.

## 2. Какие скрипты добавились и зачем

| Скрипт в `scripts/` | Что делает и зачем добавлен |
|---|---|
| `plan_crop_rotation.py` | Строит допустимые последовательности культур и выбирает общий план хозяйства по матрице переходов и ограничениям структуры посевов. Формирует таблицы и изображение карты без запуска APSIM. |
| `run_rotation_apsim_replay.py` | Переносит выбранную карту в APSIM-модель, при необходимости объединяет погоду предварительного и основного периодов, запускает APSIM и собирает годовые результаты. Нужен для оценки одной фиксированной карты. |
| `run_multiyear_rotation_optimizer.py` | Сначала рассчитывает базовый вариант выбранной карты, затем запускает NSGA-II и APSIM для вариантов управления. Сохраняет все оценки, допустимые решения Парето и сводку. Нужен для сравнения управления за несколько лет с переносом состояния почвы. |
| `manual_multiyear_apsim.py` | Готовит базовый вариант или кандидата для ручного запуска в APSIM, затем анализирует полученную SQLite-базу. Сам APSIM не запускает. Позволяет разделить подготовку, ручной расчёт и анализ. |

Новые модули в `src/`, обеспечивающие эти сценарии:

| Модуль | Роль |
|---|---|
| `rotation_planner.py` | Проверка переходов, построение последовательностей с учётом возраста многолетних трав и выбор плана для хозяйства. |
| `rotation_visualization.py` | Текстовый отчёт и изображение карты севооборота. |
| `rotation_apsim_replay.py` | Изменение календаря культур в копии APSIM-модели и объединение погодных файлов. |
| `multiyear_rotation_optimizer.py` | Пространство переменных, преобразование вектора NSGA-II в параметры управления, изменение модели кандидата и расчёт итоговых целей. |
| `fertility_constraints.py` | Проверка настроек и оценка ограничений по минеральному N и Humic. |
| `carbon_reporting.py` | Добавление отчётов по углероду в модель и чтение показателей по слоям почвы. |
| `carbon_diagnostics.py` | Проверка углеродных результатов из SQLite, сравнение с базовым вариантом и оценка изменения Humic за период. |
| `met_weather.py` | Чтение и аудит `.met`, расчёт климатических параметров и поддержка исправления единиц погодных данных. |


Удалены прежние инструменты: `evaluate_historical_bias_correction.py`, `plot_multifield_pareto.py`, `plot_multifield_quality.py`, `run_optimizer_20min_check.sh`, `run_project_checks.sh`, `validate_optimizer_smoke.py`, а также `src/historical_bias.py`. 


## 3. Какие новые выходы создают скрипты при запуске

Каталог `outputs/`, базы `.db`, логи и архивы исключены через `.gitignore`.

| Этап и каталог по умолчанию | Основные выходные файлы |
|---|---|
| Планирование: `outputs/rotation_planning/plan_<время>/` | `crop_map.csv` — карта; `alternatives.csv` — альтернативы; `selected_transitions.csv` — переходы; `plan_quality.json` — проверки; `farm_crop_counts.csv` — структура посевов при наличии настроек; `summary.json`, `crop_rotation_report.txt`, `crop_rotation_map.png`. |
| Расчёт карты: `outputs/multifield/ROTATION_2019_2023_WARMUP/replay_<время>/` | `annual_field_results.csv` — результаты по полям и годам; `annual_summary.csv` — годовые итоги; `summary.json`; `rotation_patch.json`, `model_inventory.json`, `config_snapshot.json` — сведения о подготовке расчёта. |
| Оптимизация: `outputs/multifield/MULTIYEAR_ROTATION_NSGA2_2020_2023/optimize_<время>/` | `baseline_reference.json` — базовый вариант; `evaluations.json` и `evaluations_summary.csv` — все уникальные оценки; `pareto.json` и `pareto_summary.csv` — итоговый фронт; `optimization_summary.json` — сводка; `variable_space.json` — варианты переменных; снимки конфигураций, `rotation_patch.json`, `run.log`. В `candidates/<id>/` — `result.json` и рабочие файлы расчёта кандидата. |
| Ручной расчёт: `outputs/manual_multiyear_apsim/<тип>_<время>/` | `prepared/candidate.apsimx` — модель для запуска; `manual_run_manifest.json` — инструкция и описание пакета; снимки конфигураций. После ручного запуска APSIM ожидается `prepared/candidate.db`; команда анализа создаёт `baseline_reference.json` либо `candidate_analysis.json`. С `--with-carbon` углеродная диагностика включается в JSON анализа. |

При подготовке расчётов также создаются копии `.apsimx` и объединённая погода `weather_2018_2023_warmup.met`. Базы `.db` появляются после запуска APSIM, а не от одной подготовки ручного пакета.

Планировщик, replay и оптимизатор упаковывают отчёты в архивы в корне `ApsimOptimization/`: `rotation_plan_<годы>_<время>.tar.gz`, `rotation_apsim_replay_2019_2023_<время>.tar.gz` и `multiyear_rotation_nsga2_2020_2023_<время>.tar.gz`.

Из прежних результатов удалены `results/final_20261002/bias_correction_evaluation.json`, `historical_replay_evaluation.json`, `historical_replay_evaluation.md`, `historical_replay_field_comparison.csv` и локальный README этой папки.

## 4. Прочие изменения

- `requirements.lock.txt` фиксирует версии зависимостей; в `requirements.txt` изменён только порядок строк.
- `.gitattributes` задаёт LF для текстов и сохраняет байты моделей, погоды и Excel без текстового преобразования.
- Добавлены тесты планирования, многолетнего расчёта, погоды, углеродных отчётов и ограничений; удалён тест исторической коррекции смещения.
