`historical_validation_not_ready_for_decision_optimization`. Исторический N-replay

но отклонил его после проверки 2023 года: RMSE изменился лишь с 2,521 до
2,507 т/га, Spearman остался −1. Рабочая модель не изменена. Плоские результаты

`outputs/multifield/quality_history/plots/oats_yield_candidate_rmse.png`.

Инженерный тест с искусственными числами находится в
`outputs/multifield/ENGINEERING_ONLY_b541cca218/`. Два разных кандидата успешно
прошли APSIM, чтение Report и расчёт трёх целей. Внесение озимой ржи от

Первый N-only запуск:
`outputs/multifield/DIAGNOSTIC_2023_N/optimize_982131459fc0/`. Все 16 кандидатов
APSIM завершились успешно, но случайная популяция не попала в узкую область
сохранения исходного конечного минерального N. Минимальное нормированное нарушение
составило 0,1081.

После добавления обязательной опорной точки выполнен короткий контрольный запуск:
`outputs/multifield/DIAGNOSTIC_2023_N/optimize_3137f9988d4f/`. Историческое
решение воспроизвело 3 787,24 кг сухого вещества на 2 га и нулевое нарушение
почвенных ограничений. Четыре случайных решения дали 3 936–4 057 кг, но нарушили
хотя бы одну baseline-границу. Допустимый фронт содержит опорную точку.

После разделения производственных ограничений и диагностической третьей цели
выполнен запуск `outputs/multifield/DIAGNOSTIC_2023_N/optimize_d6b3bbbdc0aa/`.
Все пять кандидатов завершились успешно, а фронт содержит три решения: 3 787,24 кг
при отклонении почвы 0; 3 936,11 кг при отклонении 0,1297; 4 057,32 кг при
отклонении 0,2482. NSGA-II теперь сохраняет наблюдаемый компромисс, а не сводит
диагностический результат к одной исторической точке.

Диагностическая чистая прибыль опорной точки равна −29 138 руб. Значение отражает
старые прокси `14,3 руб./кг зерна`, `23 000 руб./га прочих затрат` и старые цены
APSIM-форм удобрений. До появления экономики трав, отдельных цен пшеницы/ржи,
товарной влажности и фактических затрат это проверка формулы, а не оценка бизнеса.

## Воспроизведение

```bash
python3 -m pytest -q
python3 run_optimizer.py inspect
python3 run_optimizer.py baseline
python3 scripts/diagnose_rye_presets.py --run \
  --diagnostic configs/rye_refinement_fine.yaml
python3 scripts/diagnose_oats_n_response.py --run --doses 0 30 60 90 120
python3 scripts/diagnose_field_n_response.py --run --doses 0 30 60 90 120
python3 scripts/diagnose_2019_establishment_water.py --run
python3 run_optimizer.py validate \
  --config configs/multifield_2023_n_diagnostic.yaml
python3 run_optimizer.py optimize \
  --config configs/multifield_2023_n_diagnostic.yaml \
  --population 4 --generations 1
```

Расширенный диагностический запуск:

```bash
APSIM_MODELS=/absolute/path/to/Models \
  bash scripts/run_multifield_pareto_check.sh
```

По умолчанию используются `population=12` и `generations=3`; значения можно
переопределить переменными окружения `POPULATION` и `GENERATIONS`.

Для полной проверки на Ubuntu и автоматической упаковки результатов:

```bash
APSIM_MODELS=/absolute/path/to/Models \
  bash scripts/run_multifield_ubuntu_check.sh
```

Скрипт печатает точный путь к `multifield_check_<timestamp>.tar.gz`; имена
каталогов `baseline_*` и `optimize_*` вручную подставлять не нужно.

Подробная интерпретация диагностики приведена в
[CROP_DIAGNOSTICS_2023.md](CROP_DIAGNOSTICS_2023.md).
