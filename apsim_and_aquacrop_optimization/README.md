# Оптимизация посевов: три модели

Запускайте команды из корня проекта. Используется Python с установленными зависимостями; существующая локальная папка `.deps` также поддерживается.

При новой установке зависимости устанавливаются один раз:

```powershell
python -m pip install -e .
```

## Основные команды

**1. Только APSIM** — совместный подбор карты и технологии; урожай и почва рассчитываются APSIM:

```powershell
python run.py apsim --objectives yield profit humic --run
```

**2. AquaCrop + APSIM** — урожай рассчитывается AquaCrop, почвенные показатели — APSIM:

```powershell
python run.py coupled --objectives yield profit humic --run
```

**3. Только AquaCrop** — самостоятельный расчёт урожая, условной экономики и водного баланса:

```powershell
python run.py aquacrop --objectives yield profit --run
```

Без `--run` выполняется только подготовка входов. Режим `--verify-model` считает один вариант. Полный поиск может занимать часы.

## Параметры

### Экспериментальный APSIM без весеннего сброса фазы

Совместная оптимизация карты посевов и технологии на 2025–2029 годы:

```powershell
python run.py apsim --config models/apsim/configs/future_rotation_experimental_no_spring_reset_2025_2029.json --search-scope joint --run
```

Используется модель `models/apsim/simulation/experimental_no_spring_reset`. Поиск меняет 20 переменных, включая последовательности культур на десяти полях и технологии. Для яровой пшеницы, овса с подсевом и озимой ржи подбираются форма удобрения и доза азота от 0 до 210 кг N/га с шагом 30. Цели — сбор сухого вещества и сохранность Humic. Площадь каждого поля составляет 0,1 га. По умолчанию заданы NSGA-II, популяция 10, четыре поколения и seed 42.

В экспериментальной модели отключен принудительный перевод многолетников на фазу 3 первого марта. Исторические проверки показали снижение ошибки урожая и увеличение ошибки дат фаз. Параметры культур для этого изменения повторно не калибровались. Погода будущего периода задана историческими аналогами. Результаты сохраняются в `runs/future_rotation`.

- `--algorithm auto|nsga2|nsga3`: автоматически NSGA-II для 1–3 критериев, NSGA-III для 4 и более.
- `--population 20 --generations 10`: размер популяции и число поколений.
- `--output runs/my_run`: собственная новая папка результатов.
- `--config path/to/config.json`: другой конфиг выбранной модели.
- `--prepare-only`: явно подготовить входы без симуляции.

Для APSIM и связки доступны `yield`, `profit`, `mineral_n`, `humic`; дополнительные критерии задаются в конфиге. В режиме Humic только как цели он автоматически включается в набор, если пропущен.

Для самостоятельного AquaCrop доступны `yield`, `profit`, `water_use`, `water_productivity`, `drainage`, `runoff`. Humic и минеральный N этот вариант не рассчитывает.

## Где находятся настройки

| Модель | Конфиг |
| --- | --- |
| APSIM | `models/apsim/configs/future_rotation_2025_2029.json` |
| AquaCrop + APSIM | `models/apsim/configs/future_rotation_aquacrop_2025_2029.json` |
| AquaCrop | `models/aquacrop_standalone/optimization.json` |

APSIM требует установленного `Models.exe`; путь задан в настройках, его можно переопределить переменной `APSIM_MODELS`. AquaCrop использует `engines/aquacrop/field-target/debug/aquacrop-field-runner.exe`. Входы моделей находятся в `models`, стартовые технологии — в `models/apsim/data/management_reference.json`.

После клонирования GitHub-репозитория перейдите в папку `apsim_and_aquacrop_optimization`. Результаты, архив `for_me`, локальные зависимости и готовая сборка AquaCrop в Git не включены. После установки Python-зависимостей соберите движок AquaCrop установленным Rust/Cargo:

```powershell
cargo build --locked --manifest-path engines/aquacrop/field-runner/Cargo.toml --target-dir engines/aquacrop/field-target
```

Пример планирования сохраняет горизонт **2025–2029**. Погода будущих лет — исторические аналоги, экономика условная. В чистом APSIM рабочая площадь — десять полей по **0,1 га**. У связки и самостоятельного AquaCrop настройки площади остаются в их собственных входах.

## Входы и выходы каждой модели

**Входные данные** описывают поля и условия расчёта. **Переменные решения** — то, что оптимизатор может менять. **Критерии** — показатели, по которым он сравнивает рассчитанные варианты. Это три разные вещи.

### 1. Только APSIM

| Что подаётся на вход | Где находится |
| --- | --- |
| Модель почвы и культур, начальные состояния и история 2004–2023 | `models/apsim/simulation/calibrated_history/simulation.apsimx` |
| Историческая погода | `models/apsim/simulation/calibrated_history/weather.met` |
| Состояния полей за 2024, возраст травостоя и ограничения состава посевов | `models/apsim/configs/rotation_planning_2025_2029.yaml` |
| Разрешённые переходы между культурами | `models/apsim/data/rotation/rotation_transition_matrix.json` |
| Стартовые технологии, допустимые параметры посева и удобрений, экономические настройки и путь к APSIM | `models/apsim/data/management_reference.json` |
| Горизонт, погодные аналоги, площадь, критерии, область и бюджет поиска | `models/apsim/configs/future_rotation_2025_2029.json` |

**Что меняется:** в режиме `joint` — 20 переменных: по одной пятилетней последовательности для каждого из десяти полей и десять параметров технологии. Для яровой пшеницы меняются сорт, густота, глубина, междурядья и схема удобрения; для овса — густота, глубина и удобрение; для озимой ржи — густота и удобрение. Технология общая для всех появлений соответствующей культуры. Даты посева отдельными переменными не являются.

**Что получается:** карта на 2025–2029, выбранная технология, урожай по полям и годам, условная прибыль, конечный минеральный N и изменение Humic по каждому полю. Урожай и почвенные показатели рассчитывает APSIM. Выбранная выполняемая модель сохраняется в `selected_future.apsimx`, технология — в `selected_management.json`.

В текущем режиме Humic — цель без жёсткого запрета потерь. Перед симуляцией карта согласуется с заданными ограничениями состава посевов. Успешный вариант может терять Humic — это видно в результатах.

### 2. AquaCrop + APSIM

| Что подаётся на вход | Где находится |
| --- | --- |
| Новая история APSIM, погода, состояния полей, матрица переходов и стартовые технологии | Те же входы APSIM, перечисленные выше |
| Параметры связанного поиска и путь к AquaCrop | `models/apsim/configs/future_rotation_aquacrop_2025_2029.json` |
| Шаблоны полей, эффективные профили культур и справочники AquaCrop | `models/aquacrop/project.json`, `models/aquacrop/fields/`, `models/aquacrop/DATA/` и остальные файлы этой модели |

**Что меняется:** в текущем режиме `joint` также 20 переменных — карта и технология. Урожайные эффекты параметров, отсутствующие в профилях AquaCrop, дополнительно не придумываются. Например, изменение дозы N влияет на почву APSIM и расходы, но не создаёт полноценный азотный отклик урожая в AquaCrop.

**Что получается:** карта и технология, урожай **AquaCrop**, минеральный N и Humic **APSIM**, условная прибыль с учётом зарегистрированных APSIM внесений. Начальная послойная вода для AquaCrop берётся из APSIM на конец 2023 года; AquaCrop затем считает мост 2024 и период 2025–2029.

Это односторонняя связь: урожай и биомасса AquaCrop обратно в углеродный баланс APSIM не передаются. Калибровка APSIM не является калибровкой AquaCrop. Дополнительно сохраняются `selected_aquacrop.json` со ссылками на выбранные входы AquaCrop и нативные результаты внутри папки кандидата.

### 3. Самостоятельный AquaCrop

| Что подаётся на вход | Где находится |
| --- | --- |
| Список полей | `models/aquacrop_standalone/project.json` |
| Площадь, почвенные слои, начальная вода и профили культур по полям | `models/aquacrop_standalone/fields/` и `models/aquacrop_standalone/configs/fixed_field_*.json` |
| Погода и CO₂ | `models/aquacrop_standalone/configs/weather.met` и `models/aquacrop_standalone/DATA/` |
| Исходные состояния, ограничения состава и правила переходов | `models/aquacrop_standalone/planning.json` и `models/aquacrop_standalone/rotation_rules.json` |
| Критерии, бюджет, цены продукции и затраты | `models/aquacrop_standalone/optimization.json` |

**Что меняется:** десять переменных — по одной пятилетней последовательности культур на поле. Настройки выращивания берутся из собственных профилей; отдельного подбора доз N этот сценарий не выполняет. APSIM, его стартовые технологии и результаты ему не нужны.

**Что получается:** карта, урожай, выручка, затраты, условная прибыль, эвапотранспирация, дренаж, поверхностный сток и продуктивность воды. Начальная вода задана собственной моделью; по умолчанию используется полевая влагоёмкость и разогрев в 2024 году. Humic и минеральный N на выходе отсутствуют.

Выбранный вариант описан в `selected_result.json`. Его самостоятельная модель и нативные результаты находятся в `candidates/<выбранный_ID>/model/` и `candidates/<выбранный_ID>/simulation/`.

## Результаты

Каждый запуск сохраняет данные в новую папку:

- APSIM: `runs/future_rotation/...`;
- AquaCrop + APSIM: `runs/future_rotation/aquacrop/...`;
- AquaCrop: `runs/aquacrop_standalone/...`.

Внутри находятся `status.json`, настройки, результаты кандидатов, Парето, выбранный вариант, карта и `index.html`. Откройте HTML непосредственно в браузере.

При полном поиске используются следующие основные файлы:

| Файл или папка | Содержимое |
| --- | --- |
| `status.json` | Текущий этап, число оценённых вариантов и состояние расчёта |
| `scenario_inputs.json` | Фактические настройки, критерии и происхождение входных данных |
| `evaluations.json`, `evaluations.csv` | Все оценённые кандидаты и их показатели |
| `pareto.json` | Допустимые варианты, между которыми есть компромисс по целям |
| `optimization_summary.json` | Итоги поиска, число допустимых и выбранный ID |
| `selected_result.json` | Показатели и решения выбранного варианта |
| `crop_map.csv` | Карта: поле и культура на каждый год |
| `candidates/` | Входы, результаты и журналы отдельных вариантов |
| `index.html` | Отчёт данного запуска для просмотра в браузере |

В режиме подготовки или одной проверочной симуляции часть итоговых файлов поиска ещё не создаётся. У APSIM и связки дополнительно есть выбранная APSIM-модель и файл технологии; у чистого AquaCrop используются его собственные JSON и нативные входы.

Основные поля JSON: `yield_dm_kg` — общая собранная сухая масса в кг за весь оцениваемый период; `net_profit_proxy` — общая условная прибыль; `feasible` — соблюдение ограничений. Для APSIM и связки `humic` содержит начальные и конечные запасы в кг C/га, а `mineral_n_shortfall` — нормированный недобор N относительно базового расчёта. У чистого AquaCrop водные объёмы выдаются в м³, продуктивность воды — в кг сухой массы/м³. Площадь указывается в га. Общие итоги нужно отличать от показателей на гектар.

`F` — внутренний массив выбранных целей для минимизации: максимизируемые показатели передаются со знаком минус. Состав и порядок определяются выбранными критериями; для кандидатов они записаны в `objective_names`. `G` — ограничения, вариант допустим при всех `G ≤ 0`.

Успешное завершение процесса не гарантирует найденного допустимого решения: проверяйте `status` в `optimization_summary.json` и число допустимых вариантов. Выбранный вариант — представитель найденных компромиссов, а не доказанный глобальный оптимум. Показатели прибыли остаются условными для всех трёх моделей.
