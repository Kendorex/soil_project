# Оптимизация с откликом управления из APSIM

Источник сценария — `models/aquacrop/configs/rotation_fixed.apsimx`.
Исходный файл сохраняется; каждый эксперимент получает отдельную копию.
Оценка выполняется по десяти полям за 2020–2023 годы. Расчёт 2019 года
используется для формирования состояния, включая осенний посев под урожай 2020 года.

## Что добавлено

`agro/adapters/rotation_management.py` изменяет параметры действующих менеджеров
`RotationManager` и `Fertilise at sowing`: густоту, глубину, дозу и форму удобрения.
Состав севооборота, сорта, даты и междурядья сохраняются. Параметры относятся
к пшенице, прокси озимой ржи и овсу; рапс, горчица и многолетние травы
сохраняют исходное управление. Густота подсеваемых многолетних компонентов
овсяных смесей не меняется вместе с густотой овса.

В AquaCrop густота передаётся в подготовку входных файлов через изменённую
копию того же севооборота. Существующий перевод эффективных смесей сохраняется.
Для удобрений и глубины добавлен **внешний эмпирический отклик урожая** в
`agro/adapters/transferred_response.py`. Он не является новым механизмом
прорастания или азотного питания внутри расчётного ядра.

Для каждого поля, года и режима густоты:

```text
урожай гибридного AquaCrop = max(0,
    урожай нативного AquaCrop при выбранной густоте
    + урожай APSIM при выбранных удобрении и глубине
    − урожай APSIM при той же густоте и исходных удобрении и глубине)
```

Все слагаемые выражены в кг сухой массы на гектар. Упирающиеся в ноль прогнозы
регистрируются отдельно в происхождении результата. Поправка аддитивная: она
переносит абсолютное изменение урожая из APSIM, а не объявляет исходные уровни
урожайности моделей одинаковыми. Это явное допущение гибридной модели.

Поправка не пересчитывает суточный водный баланс и состояние растений AquaCrop
под действием удобрений и глубины. Такие обратные связи представлены только
в расчётах APSIM, из которых получен отклик. Поэтому итоговые гибридные урожаи
не следует считать нативными уборками из суточных файлов AquaCrop.

Почвенные показатели — минеральный азот и Humic — в гибридной задаче берутся
из того же эксперимента APSIM. В результатах это помечено как внешний
почвенный блок APSIM. Название движка результата:
`aquacrop_with_apsim_management_response`.

Это односторонний перенос: изменённая биомасса AquaCrop не возвращается в
почвенный углеродный и азотный баланс APSIM. Поэтому Humic и остаточный N
служат внешними индикаторами режима управления по APSIM, а не доказательством
согласованного баланса вещества в гибридной модели.

Такой слой согласуется с разделением движков и оптимизатора, но не заменяет
полевую калибровку и не даёт независимого подтверждения точности AquaCrop.
В самой AquaCrop влияние плодородия задаётся через локально калибруемый
стресс, а не через самостоятельный баланс доз удобрений; это описано в
[руководстве AquaCrop 7.3](https://ees.kuleuven.be/en/aquacrop/resources/reference-manual/chapter2aquacropv73.pdf).
Формула внешней поправки выше — метод этого проекта, а не формула из руководства.

## Первая конечная сетка

Используются допустимые значения из существующего многолетнего оптимизатора:

- дозы N: 0, 90 и 210 кг N/га;
- формы при положительной дозе: UreaN, NH4NO3N, UAN_N и NO3N;
- густота: нижняя либо верхняя граница для каждой группы культур;
- глубина: нижняя либо верхняя граница для каждой группы культур.

Нулевая доза не размножается по названиям форм. Получается 9 схем удобрения ×
2 связанных режима густоты × 2 связанных режима глубины = 36 сочетаний.
Каждое сочетание сначала измеряется реальным расчётом APSIM. Отдельные
референсы APSIM и AquaCrop рассчитываются для двух режимов густоты.

Настройки NSGA-II — популяция 10, четыре поколения, seed 42 — берутся из
`models/apsim/configs/multiyear_rotation_nsga2_2020_2023.yaml`. Алгоритм работает
через общий модуль `agro.optimization`. Поскольку вся конечная сетка уже
измерена для переноса отклика, дополнительно вычисляется полный фронт Парето
среди всех 36 сочетаний. История NSGA-II сохраняется отдельно от этого полного
фронта. Это не полный независимый перебор всех исходных политик культур.

Четыре дополнительные комбинации с дозами 60 и 150 кг N/га отложены для проверки
линейной интерполяции отклика APSIM. Они не участвуют в итоговом поиске.
Эта проверка измеряет ошибку интерполяции расчётного отклика, а не ошибку
AquaCrop относительно реальных полевых наблюдений. Итоговый поиск ограничен
измеренными узлами и не применяет интерполяцию или экстраполяцию.

## Цели и допустимость

Сохранены три смысла целей существующего алгоритма:

1. Максимум собранной сухой массы по всем полям и годам.
2. Максимум диагностического экономического результата.
3. Минимум нормированного дефицита остаточного минерального N относительно
   исходного сценария без оптимизации.

Экономика использует исходные диагностические цены, стоимость фактических
внесений удобрений из журналов APSIM и заданные постоянные затраты. Нормировка
дефицита N выполняется по исходному значению каждого поля и года. Цены для
рапса, горчицы и кормовой массы не подтверждены и в этой серии не добавляются.

Жёсткое ограничение: Humic на каждом поле в конце 2023 года должен быть не
меньше собственного запаса на 31 декабря 2019 года. При нарушении хотя бы на
одном поле вариант недопустим; улучшение другого поля не компенсирует потерю.
Если допустимых вариантов нет, отчёт так и сообщает. Максимальный урожай без
учёта ограничений и вариант с наименьшим нарушением выводятся как диагностика,
а не как допустимые агрономические рекомендации.

## Запуск и результаты

```powershell
python -m agro.management_study --workers 2
```

Повторный запуск продолжает успешные эксперименты по совпадающим входным данным.
Артефакты неудачных попыток сохраняются отдельно. Для нового исследования:

```powershell
python -m agro.management_study --workdir runs/management_study_new --workers 2
```

Статус — `runs/management_optimization_20261027/status.json`. Полные расчёты,
проверка, история поиска и JSON результатов находятся там же. Итоговый отчёт
сохраняется в `runs/management_optimization_20261027/report/index.html`.
