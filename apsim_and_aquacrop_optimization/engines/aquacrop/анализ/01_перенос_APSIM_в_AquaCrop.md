# Какие данные APSIM можно перенести в AquaCrop

Таблица описывает текущий проект. «Можно» не означает, что существующий адаптер уже использует эту возможность.

## Конфигурация поля, сроки и управление

| APSIM: источник | AquaCrop / адаптер | Возможность переноса и текущее состояние |
| --- | --- | --- |
| Simulation / Zone, имена Field1…Field10 | project.json, fields/fixed_field_*.json | Прямой: каждому полю соответствует независимый профиль и каталог результатов. |
| Clock.Start / End | окна расчёта .PRM и план запуска | Прямой: период 2019–2023. Период культуры внутри него задаётся отдельно. |
| Zone.Area | метаданные площади | Извлекается в source_mapping.json. AquaCrop рассчитывает урожай на единицу площади; валовой сбор требует отдельного умножения на гектары. |
| RotationCrops / RotationCultivars | выбор каталожного .CRO | Прямо переносятся названия и порядок культур. Биология сорта — только приближение; название файла не подтверждает сортовую калибровку. |
| RotationSowingDates и реальные события sow | начало окна культуры | Переносятся даты. Для озимого сорта учитывается осенний посев предыдущего года; начальная озимая культура 2019 года ограничена началом имеющегося расчёта. |
| RotationHarvestDates, HarvestCrops, Uses | конец окна, график укосов .MAN, выбор сравниваемой массы | Даты и назначение продукции переносятся; зерно, сено и зелёная масса различаются. Проверяются фактические события Native HarvestReport. |
| RotationPopulations, растений/м² | .CRO: planting density, растений/га | Прямой пересчёт ×10 000. В эффективной смеси густоты компонентов суммируются; это уже приближение смеси. |
| RotationSowingDepths, мм | возможно использовать при оценке всходов | Извлекается и сохраняется, но прямого поля глубины посева в текущем .CRO нет; влияние на всходы не воспроизводится механически. |
| RotationRowSpacings, мм | косвенная оценка покрытия | Сохраняется в описании компонентов; в текущий .CRO напрямую не переносится. |
| PastureAges и фактическая дата закладки | возраст многолетнего посева | Можно извлечь возраст. Текущий перенос удерживает сведения о реально посеянном сорте, но реконструирует биологическое состояние между окнами. |
| TerminationDate / WinterDiebackDate | завершение окон, правила реконструкции | Даты доступны; точное отмирание отдельных органов, зимняя гибель и весеннее отрастание APSIM не воспроизводятся. |
| Смесь Oats + RedClover + PlantainForage | одна эффективная культура, затем подлесок/подсев отдельным окном | Приближение, согласованное для этого проекта. Одновременная конкуренция видов за свет, воду и азот не переносится. |
| FractionLive/DeadToRemove и ToResidue органов | укос .MAN, остаточное покрытие и продукция | Можно извлечь доли удаления. Они не равны HIo и не копируются в него; точная органная уборка APSIM текущим адаптером не повторяется. |
| Fertilise at sowing: тип и количество N | агрегированный стресс плодородия .MAN | Доступны дозы и сроки, но прямого перевода кг N/га в процент стресса нет. Текущее значение стресса управления — 0; это допущение, а не воспроизведение азотного питания. |
| Полив, если задан событиями | .IRR / отдельная последовательность поливов | В принципе сопоставимы дата и слой воды; текущий сценарий дождевой, автоматического переноса произвольного APSIM-менеджера полива нет. |
| Остатки и обработка поверхности | мульча/поверхностные практики .MAN | Требуется оценить покрытие и воздействие на испарение/сток. Масса остатков и процент покрытия не тождественны; сейчас mulch_cover_percent=0. |

## Погода и атмосфера

| APSIM: источник | AquaCrop | Возможность переноса и текущее состояние |
| --- | --- | --- |
| weather_rotation.met: year, day | непрерывные ежедневные даты | Прямой; проверяются покрытие периода и отсутствие разрывов. |
| mint, maxt, °C | Weather.Tnx | Прямой, с округлением записи. |
| rain, мм/сут | Weather.PLU | Прямой, с округлением записи. |
| latitude | расчёт внеземной радиации Ra для ETo | Извлекается; широта участвует во внешнем расчёте ETo. |
| radn, МДж/м²/сут | отдельного прямого ежедневного входа радиации в текущем движке нет | Сохраняется для аудита. В используемой оценке ETo по Харгривсу применяется Ra из широты и даты, а не измеренная radn. |
| Внутренняя потенциальная эвапотранспирация APSIM | Weather.ETo, мм/сут | Не копируется. ETo заново оценивается по Tmin/Tmax/широте методом Харгривса; это источник различий водного баланса. |
| CO₂, если доступен сопоставимый ряд | MaunaLoa.CO2 | В текущем переносе берётся отдельный файл AquaCrop из fields/*.json, а не извлекается автоматически из APSIM. Проверять согласованность концентраций отдельно. |

## Почва и начальное состояние

Физико-химические свойства почвы по условию задачи изменять нельзя. Ниже описано чтение существующих значений и различие их представлений; это не рекомендация подгонять почву.

| APSIM | AquaCrop | Преобразование / ограничение |
| --- | --- | --- |
| Physical.Thickness, мм | Soil.SOL: толщина, м | Прямой: ÷1000; в текущем поле 7 исходных слоёв. |
| Physical.SAT, м³/м³ | SAT, об.% | Прямой: ×100. |
| Physical.DUL, м³/м³ | FC, об.% | Сопоставление полевой влагоёмкости: ×100. Это перенос выбранной характеристики, не идентичность гидрологических моделей. |
| Physical.LL15, м³/м³ | WP, об.% | ×100. Не заменяется культуроспецифическим SoilCrop.LL. |
| Physical.KS, мм/сут | Ks, мм/сут | Прямой по величине. Вода движется по разным алгоритмам, поэтому одинаковый Ks не обеспечивает одинаковый дренаж. |
| Water.Thickness / InitialValues, м³/м³ | plan.json: initial_water → начальные отсеки ядра | Прямой вход с согласованием вертикальной сетки; передаётся через прямой движок, не через автоматически загружаемый внешний файл начальных условий. |
| Swim3.CN2Bare | Curve number .SOL | Сопоставление параметра голой почвы; текущий генератор округляет до целого. Общая формулировка стока не идентична SWIM. |
| Physical.Rocks | гравий .SOL | В текущей конфигурации значения Rocks нулевые; генератор записывает 0 константой. Для ненулевых значений нужен отдельный проверенный перенос определения доли камней. |
| SoilCrop.XF, KL, LL по видам | penetrability, извлечение корнями, WP | Прямого соответствия нет. Сейчас penetrability=100%, параметры извлечения взяты из .CRO; KL/XF не преобразуются автоматически. |
| AirDry, BD, песок/ил/глина | косвенное обоснование испарения/гидравлики | Можно извлечь; текущий генератор не передаёт их отдельными численными строками .SOL. Изменять для подгонки запрещено. |
| Chemical.PH, Organic.Carbon, SoilCNRatio, FOM, FBiom/FInert | нет прямого полного почвенно-биогеохимического аналога | Сохраняются в исходнике/снимке анализа; кислотность, минерализация и оборот органического вещества APSIM не воспроизводятся. |
| NO3, NH4, Urea по слоям | нет прямого переноса азотных пулов | Нельзя подменять минеральный азот солёностью AquaCrop или процентом плодородия без отдельной модели/калибровки. |
| Chemical.EC, если задан | начальная солёность с согласованными единицами/методом измерения | В просмотренном Field1 EC=null. Нельзя считать любую EC равной ECe; текущий адаптер химический профиль автоматически не переносит. |
| SWIMSetLowerBC: seepage, -500 и параметры SWIM | грунтовая вода/капиллярный подъём AquaCrop | Не переносится один к одному. Граничное условие SWIM не равно измеренной глубине УГВ; CRa/CRb в .SOL сейчас шаблонные. |

Текущие дополнительные настройки .SOL: REW=2 мм (временное допущение), penetrability=100%, gravel=0, CRa=-0.390600, CRb=1.255639. Они **не извлечены** из физико-химической характеристики APSIM. При существующем запрете на изменение почвенных входов их здесь только документируем; изменение потребовало бы отдельного решения пользователя.

## Параметры растений: что можно восстановить, но нельзя копировать напрямую

| Данные APSIM | Возможное использование в AquaCrop | Что делает текущий перенос |
| --- | --- | --- |
| Даты всходов, цветения, налива, зрелости из отчётов | Календарь дней/GDD, длительность формирования HI | Базовые сроки в основном заданы долями окна: корни 0.75, старение 0.85, цветение 0.55, HI 0.35 длительности; это эвристики. В варианте ВНИИМЗ есть уточнение по наблюдаемым срокам, а не извлечение физиологии APSIM. |
| LAI, зелёное покрытие, k поглощения света | CC0, CCx, CGC, CDC | Нужен подбор по сопоставимому временному ряду. Приближение CC≈1−exp(−k·LAI) требует согласования геометрии и определения покрытия; автоматически не реализовано. |
| RootDepth и динамика водопотребления | Zmax, сроки роста корней, Sx | Возможен подбор по динамике, но KL нельзя просто записать как Sx. Сейчас Zmax=1.5 м, Zmin=0.3 м — параметры шаблонов. |
| Биомасса + транспирация + ETo + CO₂ | WP* | Можно оценить эффективную WP* на сопоставимых рядах. RUE, основанная на радиации, не равна WP*. Сейчас используются шаблонные/подобранные значения. |
| Сухой урожай + надземная сухая биомасса | наблюдаемый HI и калибровка HIo | Отношение масс при одном сроке даёт реализованный HI, а HIo — потенциальный. Нельзя механически объявлять их одинаковыми при стрессе. |
| Температурные/водные функции PMF | пороги и формы стрессов .CRO | Только переоценка реакции, а не прямое копирование массивов X/Y. |
| Запасы и повторное отрастание многолетника | доли запасания/мобилизации .CRO | Требуется отдельная оценка; органные углеродные/азотные пулы APSIM не переносятся как идентичный checkpoint. |

## Что сравнивать в результатах

Сохраняется запрос пользователя сравнивать урожай **Yield**, а не общую биомассу. Для ежегодной убранной продукции текущая обвязка использует native `HarvestReport.YieldDMTHa`, отдельно сохраняя стоящий дневной Yield. Для сена и зелёной продукции важно, какая часть действительно удалена, какие виды собраны, сколько укосов суммировано и что остаётся в поле. Эти величины могут отличаться от стоящего Yield на последнюю дату.

Все сравнения с Excel имеют единицы т/га: зерно или сухая кормовая масса по подтверждению пользователя. Поле сухого вещества .CRO не применяется повторно к уже сухой массе. Если исходная величина выражена в г/м², перевод в т/га равен ×0.01; нельзя применять этот коэффициент к уже готовому YieldDMTHa.
